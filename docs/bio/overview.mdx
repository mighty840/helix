## Why Bio Safety?

DNA sequences that violate certain chemical constraints are:

- **Hard to synthesize** — oligo houses reject or fail on problematic motifs
- **Unstable in storage** — prone to hydrolysis, oxidation, or depurination
- **Prone to sequencing errors** — homopolymers and hairpins confuse polymerases

The `helix-bio` crate scans for violations and swaps synonymous opcode codons to resolve them.

## Constraints

### GC Content

| Metric | Limit |
|--------|-------|
| GC fraction per 100-nt window | 40%–60% |

GC content outside this range causes:
- All-AT: prone to strand separation and AT-repeat instability
- All-GC: prone to G-quadruplex formation and synthesis failure

### Homopolymer Runs

**Limit: ≤ 4 identical consecutive bases**

```
AAAAA   ← violation (run of 5)
AAAA    ← allowed (run of 4)
```

Long homopolymers are the most common source of sequencing indels (polymerases slip).

### Dinucleotide Repeats

**Limit: ≤ 4 consecutive dinucleotide repeats**

```
ATATATATAT  ← violation (5× AT)
ATATATAT    ← allowed (4× AT)
```

### Palindromes (Hairpins)

**Limit: ≤ 8-bp palindrome**

A palindrome in a single-stranded DNA context is a sequence that is its own reverse complement:

```
ACGT ACGT → reverse complement of ACGT ACGT = ACGT ACGT  ← 8 bp, allowed
GCATGCATGCAT → spans 12 bp → violation
```

Hairpin formation causes premature termination during synthesis and confuses sequencing reads.

## The Optimizer

`helix_bio::SequenceOptimizer` implements a greedy swap strategy:

1. Run the linter to find all violations
2. For each violating codon that has a synonymous opcode: swap to the synonym
3. Re-run the linter on the modified sequence
4. Repeat until no violations or no more swaps available

```rust
use helix_bio::SequenceOptimizer;

let optimizer = SequenceOptimizer::new();
optimizer.optimize(&mut instruction_codons);  // in-place
```

The optimizer only swaps codons with valid synonyms (opcodes 0x00–0x0F). Operand codons, register refs, and immediates are never modified — this preserves program semantics exactly.

## Linter API

Use the linter standalone to audit a sequence without modifying it:

```rust
use helix_bio::{GcScanner, HomopolymerScanner, DinucleotideScanner, PalindromeScanner};
use helix_isa::DnaSequence;

let seq = DnaSequence::parse("ACGTACGT...").unwrap();
let bases: Vec<Base> = seq.bases().collect();

let gc_violations = GcScanner::scan(&bases);
let hp_violations = HomopolymerScanner::scan(&bases);
let dn_violations = DinucleotideScanner::scan(&bases);
let pal_violations = PalindromeScanner::scan(&bases);
```

Each scanner returns a `Vec<Violation>` with position and description.

## Violation Types

```rust
pub struct Violation {
    pub position: usize,   // base index in the DNA sequence
    pub length: usize,     // span of the violation
    pub kind: ViolationKind,
}

pub enum ViolationKind {
    GcContent { fraction: f32 },
    HomopolymerRun { base: Base, length: usize },
    DinucleotideRepeat { dinucleotide: [Base; 2], count: usize },
    Palindrome { length: usize },
}
```

## Integration in the Pipeline

The bio optimizer runs between the assembler and the ECC encoder:

```
helix-asm → raw codons → helix-bio optimizer → helix-ecc encoder → DNA string
```

In the assembler CLI, optimization is enabled by default. Pass `--no-bio-opt` to skip it (useful for testing).
